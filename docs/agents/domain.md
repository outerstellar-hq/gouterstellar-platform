# Domain documentation

This repository has one context.

Before changing architecture or public interfaces:

1. Read the root `CONTEXT.md` when it exists.
2. Read relevant decisions under `docs/adr/`.
3. Use the established domain terms in issues, code, tests, and documentation.
4. Surface any conflict with an accepted ADR instead of silently overriding it.

Create or sharpen `CONTEXT.md` only when implementation work resolves a real
domain term. Consumer product concepts do not belong in this context.
