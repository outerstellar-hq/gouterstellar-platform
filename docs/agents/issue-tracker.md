# Issue tracker: GitHub

Issues and implementation work for this repository live in GitHub Issues. Use
the `gh` CLI from this checkout so the remote selects the repository.

## Conventions

- Create work with `gh issue create` and a complete Markdown body.
- Read the issue body, labels, and comments before claiming files.
- Record the branch, exact file claim, and intended outcome before editing.
- Release the claim after the pull request merges.
- Keep consumer-repository work in a separately scoped consumer issue.

## Skill mapping

When a skill says to publish work, create a GitHub issue. When it asks for the
relevant ticket, read the issue and its comments with `gh issue view`.
